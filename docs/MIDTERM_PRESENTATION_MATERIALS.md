## 2. 报告摘要（可改写引用）

本项目面向会议纪要中行动项难识别、责任与截止时间常缺失、创建后缺乏验证和跟进的问题，开发了状态机驱动的会议行动智能体。用户配置模型 API 后，系统抽取候选任务和原文证据，对缺失或冲突信息主动澄清，提供优先级理由，待人工批准后经本地任务连接器创建任务、回读验证并追踪至完成。中期版本新增运行内自然语言对话：可回答当前澄清、查询进度、请求刷新追踪，并对唯一任务提出状态或字段变更；涉及写入的操作须再次确认。项目 Prompt Skill 与用户 Markdown Skill 分层，后者允许用户用自然语言定义团队称呼和业务规则，但不能改变审批与工具权限。现阶段已通过 47 项自动化测试、生产构建和隔离的真实模型与桌面/移动浏览器冒烟；真实第三方连接器、生产级权限与数据评测留待下一阶段。

## 4. 新增自然语言对话能力的准确口径

| 用户意图 | 当前处理 | 是否调用对话模型 | 写入与边界 |
|---|---|---|---|
| 回答当前澄清 | 将回答绑定现有问题，更新对应任务和待处理事项 | 聊天框发送时调用 | 不能凭空绑定不存在的问题；已解决问题保留历史 |
| 查询运行/任务情况、解释 | 模型根据当前运行上下文生成答复 | 聊天框发送时调用 | 解释文本尚无逐字段事实校验，不能当成已核实的第三方实时数据；专项样本仍待复核 |
| 请求刷新追踪 | 规划为刷新意图，读取当前已验证任务 | 聊天框发送时调用 | 仅追踪/完成阶段可用，不能创建任务 |
| 修改任务状态 | 唯一定位已验证任务，先显示目标状态提案 | 聊天框发送时调用 | 只在追踪阶段、确认后写入；取消或目标不明不写入 |
| 修改标题、描述、负责人、截止日期、优先级 | 唯一定位任务并展示逐字段旧值→新值 | 聊天框发送时调用 | 审批前或追踪中可提案；确认后才修改，追踪中回读；日期须明确到年/月/日 |
| 页面澄清表单、审批按钮、状态快捷控件、确认提案 | 受控状态机执行并给出回报 | **不额外调用**对话模型 | 原审批与二次确认仍是权限边界 |

初次提交纪要会单独调用分析模型；只有在运行的聊天框发送消息才触发对话模型。模型规划受限意图，不能直接调用任意工具。当前不能靠自由文本直接审批创建，不能任意增删任务、跨运行改任务、跳过确认或修改已完成/失败运行。模糊目标、不完整日期、过期提案会要求澄清或拒绝。真实模型实测过含糊“开始吧”追问、明确状态变更确认，以及截止日期只给年份时追问、完整日期确认回读；十套对话人工样本尚未全部逐项执行。

## 5. 后期开发目标（只保留两项）

1. **接入真实任务平台**：选定一个平台，完成授权、字段映射、重复请求不重复创建、失败可解释和逐字段回读；沿用中期已经验证的人工审批边界。
2. **建立效果评测**：准备脱敏且人工标注的会议样本，分别统计任务识别、负责人/日期抽取、澄清质量、对话意图和端到端创建/验证成功率。47 项工程测试不能替代这些指标。

其余工程事项（身份权限、生产数据库、异步恢复等）只有在部署方案确定后再拆成实现任务，不在本次 PPT 中扩写成没有验收标准的口号。

## 7. 删减建议与答辩防误读

- PPT 正文只保留一个状态图、一张分层架构图、约 6-8 张关键 UI 图；多余截图放备份页或报告附录。图号多是采集清单，不等于每张都要挤进 9 页。
- 不要把内部提示词文件数量当成产品功能数量。对外只需说明两层：会议分析会调用“任务提取、完整性检查、优先级解释”，对话会调用“对话编排、任务编辑”；审批、验证、追踪由状态机和工具守卫执行。
- 不要把“用户 Markdown Skill”说成模型微调，也不要把本地规则测试辅助说成用户可选的本地模式。
- 不要用单次 DeepSeek 冒烟、47 项工程测试或演示截图推断真实会议数据的准确率。
- `LTH-*` 是本地连接器 ID；真实应用接入是后期目标。
- 验收文档里的旧版基线和本轮隔离运行要分清；报告/PPT 以 2026-09-21 最新状态为准，旧版的 42 项测试不作为当前数字。
